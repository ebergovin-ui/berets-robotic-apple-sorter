# Архитектура BERETS Classic

## Назначение

Программная система разделяет пользовательский интерфейс, технологическую логику, хранение состояния, компьютерное зрение и низкоуровневое управление оборудованием.

## Основные компоненты

| Компонент | Назначение |
|---|---|
| `app.py` | маршруты Flask, авторизация, API и выдача страниц |
| `state.py` | согласованное состояние комплекса и журнал событий |
| `hardware.py` | единственная точка доступа к UART и GPIO |
| `gate_controller.py` | сопровождение яблока и управление заслонками |
| `dispenser.py` | периодическая подача единичных объектов |
| `route_store.py` | хранение и проверка маршрутных точек |
| `route_executor.py` | последовательное выполнение маршрута |
| `container_exchange.py` | сценарий замены заполненного контейнера |
| `container_inventory.py` | учёт пустых и заполненных контейнеров |
| `yolo_bridge.py` | камера, модель, сопровождение и передача событий |
| `vision_zones.py` | калибруемые области изображения |
| `readiness.py` | причины, запрещающие автоматический цикл |

## Поток данных

1. Видеомодуль получает кадр и формирует обнаружения.
2. Обнаружение проходит пороги достоверности, сопровождение и проверку зоны.
3. Диспетчер выбирает канал и формирует задание заслонке.
4. После заполнения контейнера сортировка останавливается.
5. Координатор выбирает маршрут, уровень полной и уровень пустой стопки.
6. Исполнитель передаёт каждую точку аппаратному шлюзу.
7. Состояние и этап операции отображаются в веб-интерфейсе и цифровом двойнике.

## Принципы безопасности

- HTTP-обработчики не формируют аппаратные сигналы напрямую.
- Реальные интерфейсы отключены без явных флагов окружения.
- Рельса блокируется без подтверждённой калибровки и поиска исходного положения.
- Маршрутные значения проверяются по программным диапазонам.
- Одновременный доступ нескольких процессов к сервошине запрещён.
- Потеря камеры или требуемого контейнера запрещает продолжение автоматического цикла.

## Следующее поколение

В ROS 2 эти компоненты станут независимыми узлами, а выполнение маршрута — отменяемым действием с обратной связью. Аппаратный узел сохранит исключительное владение GPIO и UART.
